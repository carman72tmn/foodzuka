# Отчет: Диагностика и оптимизация нагрузки CPU и RAM сервера

**Дата**: 04.09.2026  
**Сессия**: loggemini_2026-09-04_resource_cpu_ram_boost  
**Статус**: Выполнено успешно  

## 1. Исходные симптомы
- Жалоба пользователя: чрезмерное потребление оперативной памяти и периодическая перегрузка процессора сервера.

## 2. Результаты глубокой диагностики
1. **Обнаружен скрытый краш-луп Telegram-бота (oodtech-bot)**:
   - Бот aiogram падал с TelegramNetworkError: HTTP Client says - Request timeout error.
   - Docker перезапускал контейнер каждые 30-40 секунд (estart: always).
   - Каждый рестарт сжигал до **50.5% CPU** одного ядра на инициализацию модулей Python.
2. **Фрагментация и утечка памяти в Celery Worker (oodtech-worker)**:
   - Процессы воркера занимали 400-600 МБ RAM из-за отсутствия лимита жизненного цикла рабочих процессов.
3. **Зависшие соединения PostgreSQL (idle in transaction)**:
   - В database.py в FastAPI dependency get_session() сессии возвращались в пул соединений без явного session.rollback() в блоке inally:.

## 3. Проведенная оптимизация
1. **ot/main.py**:
   - Увеличен таймаут aiohttp-сессии до 30 секунд.
   - Запуск dp.start_polling обернут в цикл с обработкой TelegramNetworkError и задержкой syncio.sleep(15).
   - Контейнер больше не крашится, процессор стабильно разгружен до **0.00% CPU**.
2. **docker-compose.yml**:
   - В сервис worker добавлены флаги --concurrency=2 --max-tasks-per-child=100. Потребление RAM воркером снизилось с 400 МБ до **230 МБ** (-42%).
   - В сервис ot добавлен том ./bot:/app.
3. **ackend/app/core/database.py**:
   - В get_session() добавлен гарантированный session.rollback() в inally:. Количество idle in transaction в PostgreSQL снижено до строгого **0**.
