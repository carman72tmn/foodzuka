# Log: Stabilize Address Synchronization
Date: 2026-05-05 00:40

## Problem
Recurring `NotNullViolation: null value in column "street" of relation "client_addresses_history" violates not-null constraint`.
This error poisoned the database transaction and prevented subsequent order updates in the same sync session.

## Cause
- `iiko_sync_service.py` was passing `None` to `street` and `city` fields when Iiko API data was missing or incomplete.
- `customer_tasks.py` (Celery tasks) had similar issues in `_sync_guest_addresses` and `import_customers_from_file_task`.

## Fixes
1. **Normalization**: Forced `street` to default to `""` and `city` to `"Тюмень"` (default city) in all code paths creating `ClientAddressHistory`.
2. **Transaction Handling**: 
   - Added `session.rollback()` in `process_iiko_order` top-level `except` block to ensure the session is cleared if any part of the process fails.
   - Note: The `ensure_customer_from_order` call was already wrapped in a `try/except`, but lacked a rollback, which led to subsequent `InternalError` (aborted transaction).

## Files Modified
- `backend/app/services/iiko_sync_service.py`
- `backend/app/tasks/customer_tasks.py`
