## Задача: Проверка и исправление отображения входящих транзакций с терминалов эквайринга, СБП и QR-кодов в Мониторе Т-Банк.

### Проведенный анализ
1. **Анализ БД**: Проверка таблицы `tbank_statements` показала отсутствие записей с терминалов эквайринга (номера `2332089853` и `3190040478`), присутствовали только выписки по основному счету.
2. **Анализ логов воркера**: Обнаружено, что периодическая задача `sync_tbank_terminals_task` опрашивает API за последние 2 часа, но сегодняшние операции по терминалам произошли более 2 часов назад (в 07:13 и 07:15 UTC при текущем времени 09:50 UTC). Из-за этого при периодическом опросе возвращалось `processed: 0`.
3. **Анализ ошибок API Т-Банка**: В логах зафиксировано, что при опросе нескольких терминалов подряд API Т-Банка на второй запрос возвращал ошибку `429 Too Many Requests`. Это связано с отсутствием задержки между запросами в цикле.
4. **Анализ сопоставления способов оплаты**: В `backend/app/api/bank.py` метод оплаты определялся по ключевым словам. Для назначения платежа `"Оплата через POS-терминал {term_key}"` метод определялся как `"Перевод"`, а во фронтенде `tbank-payments.vue` фильтр по эквайрингу (вкладка "Эквайринг (Карты)") ожидал слова `"эквайринг"` или `"карт"`. В итоге операции по терминалам попадали в "Прямые переводы" вместо "Эквайринг".

### Внесенные изменения
1. **Фоновая задача `sync_tbank_terminals_task`** (`backend/app/tasks/tbank_tasks.py`):
   - Увеличена глубина опроса терминалов с 2 до 12 часов.
   - Добавлена искусственная задержка `time.sleep(2.0)` между запросами к разным терминалам в цикле для исключения ошибок `429 Too Many Requests`.
2. **API эндпоинт `/payments`** (`backend/app/api/bank.py`):
   - Добавлена автоматическая классификация транзакции как `"Эквайринг"`, если длина номера счета `len(account_number) < 15` (признак терминала, так как расчетные счета имеют длину 20 символов) либо если назначение платежа содержит слова `"pos"`, `"терминал"`, `"эквайринг"`.
