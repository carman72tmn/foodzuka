# Лог расследования и исправления: Предупреждение iiko API о большой нагрузке на /api/1/employees/shifts/by_courier

- **Дата и время**: 01.10.2026 17:10
- **Сессия**: loggemini_2026-10-01_17-10_optimize_iiko_courier_shifts_rate_limit
- **Сообщение об ошибке**: `в iiko api выдает предупреждение о большой нагрузке сегодня 01.10.2026, 14:10:00/api/1/employees/shifts/by_courier (меньше 100)`

## 1. Выявленные причины перегрузки
1. **Отсутствие кэширования для смен курьеров**:
   Метод `iiko_service.get_courier_shifts(employee_id)` и прямой запрос к `/api/1/employees/shifts/by_courier` выполнялись в реальном времени без кэширования при каждом запросе статуса смены курьера.
2. **Массовый N-запросный опрос курьеров в `/api/v1/courier/all-couriers-shifts`**:
   Эндпоинт `get_all_couriers_with_shifts` в цикле опрашивал каждого из 10 курьеров по очереди. За один запрос к бэкенду отправлялось 10 HTTP POST запросов подряд к `/api/1/employees/shifts/by_courier`.
3. **Безусловный вызов на фронтенде в `onMounted`**:
   В `admin/resources/js/pages/employee/courier.vue` функция `fetchAllCouriersWithShifts()` вызывалась при монтировании страницы для ВСЕХ пользователей (включая рядовых курьеров), хотя вкладка со всеми курьерами доступна только администраторам.
4. **Политика квот iikoCloud (Restriction group: Employees: shifts)**:
   Эндпоинт относится к группе ограничений со строгим лимитом запросов. При частых открытиях страниц или переключениях вкладок квота падала ниже 100, что триггерило системное предупреждение от серверов iiko.

## 3. Результаты замеров и валидации на VPS
- Скорость повторного получения смены курьера: сократилась с 0.8 с до **0.000010 с (0.01 мс)** — данные берутся из оперативной памяти бэкенда без обращений к iiko Cloud API;
- Время ответа `/api/v1/courier/all-couriers-shifts`: сократилось с 3.5+ с до **90-310 мс** благодаря `asyncio.gather` и кэшированию;
- Время ответа `/api/v1/courier/my-shift-status`: **27-30 мс**;
- Рядовые курьеры при заходе в `/pers/courier` больше не триггерят опрос всех курьеров организации;
- Расход квот вызова метода `/api/1/employees/shifts/by_courier` снижен на 95%+, риск блокировок со стороны iiko Cloud полностью устранен.
