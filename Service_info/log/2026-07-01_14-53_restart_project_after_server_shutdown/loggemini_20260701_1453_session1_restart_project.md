**Дата**: 2026-07-01

## Описание задачи
Пользователь запросил полный перезапуск проекта для устранения ошибок в работе, возникших после отключения (сбоя) сервера.

## Предварительный анализ
1. Проведен опрос состояния docker-контейнеров на VPS (`ssh vezuroll "cd foodzuka && docker compose ps -a"`).
2. Выявлено, что контейнер Celery воркера (`foodtech-worker`) находился в статусе `Exited (1) 8 days ago` (упал 8 дней назад).
3. Анализ локального файла `docker-compose.yml` показал, что для сервиса `worker` отсутствовала инструкция автоперезапуска `restart: always` (в то время как в `docker-compose.prod.yml` она присутствовала).
4. Из-за отсутствия `restart: always` в основном `docker-compose.yml`, при перезагрузке/отключении VPS-сервера контейнер воркера не поднялся автоматически, что привело к остановке фоновых задач (синхронизация заказов, клиентов, рассылка сообщений).

## Выполненные действия
1. В локальном файле `docker-compose.yml` для сервиса `worker` добавлена директива `restart: always`.
2. Измененный `docker-compose.yml` успешно синхронизирован с VPS с помощью `scp`.
3. Выполнен полный останов всех контейнеров на VPS с помощью `docker compose down`. Все 9 контейнеров и сеть были корректно удалены.
4. Выполнен чистый холодный запуск проекта на VPS с помощью `docker compose up -d`. Все 9 контейнеров успешно созданы и запущены в фоновом режиме.
5. Очищен кэш Laravel (конфиги, роуты, вью) в контейнере `foodtech-admin` с помощью `php artisan optimize:clear` для исключения зависших состояний.
6. Выполнена верификация статуса контейнеров через `docker compose ps` и логов Celery воркера через `docker compose logs worker`.

## Результаты верификации
