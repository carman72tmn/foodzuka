# Лог задачи: Оптимизация и стабилизация Мультичата
Дата создания: 2026-10-01 19:00:00
Задача: Ускорение мультичата, устранение лагов/задержек, кеширование сообщений, реальное время (WebSocket/SSE/Long-polling/Real-time), поддержка чата в заказах и отдельного мультичата, оперативная доставка из ВК (группы, сообщества, личные аккаунты) и МАКС, корректное отображение содержания сообщений, логинов и аватарок.

## 1. План диагностики и аудита:
- Проверить текущую архитектуру мультичата (бэкенд API, модели, вебсокеты/поллинг, сервисы интеграции VK и MAX).
- Проверить фронтенд (компоненты мультичата, store/state, кеш, реактивность, отображение в диалогах заказов и отдельной странице).
- Проверить статус сервисов на VPS (docker compose ps, логи бэкенда, celery/воркеров, redis, базы данных).
- Выявить узкие места производительности и баги отображения.

## 2. Выявленные критические проблемы:
1. **Генерация мусора в MAX**: В `max_bridge_service.py` (`sync_pymax_dialogs`) пустые диалоги каждые пару минут порождали фейковые сообщения со словом `"Диалог MAX"`. Таблица `multichat_messages` была раздута до 450 000 строк, эти пустые чаты постоянно висели в топе.
2. **Сброс медиа-сообщений в ВК**: В `vk_service.py` условие `if not text: return` отбрасывало любые входящие картинки, стикеры, аудио/голосовые сообщения без текста.
3. **Падение транзакций БД при привязке телефона**: Ограничение `UNIQUE` на индексе `ix_vk_users_phone` приводило к сбою всей сессии SQL при привязке одного телефона к разным VK ID.
4. **Задержка личного аккаунта ВК (2 минуты)**: Проверка личного аккаунта висела на интервале APScheduler раз в 2 минуты вместо моментального User LongPoll.
5. **Ошибка 403 Forbidden для аватарок**: Браузер передавал реферер сайта на домены `i.oneme.ru` (MAX) и `vkuserphoto.ru` (VK), вызывая ошибку 403.
6. **Тормоза интерфейса (мерцание и белый экран)**: При клике на диалог вызывалось `messages.value = []` и отправлялся сетевой GET `/history`, реактивного кэша в памяти не было.
7. **Конфликт компонентов на странице заказов**: В `orders/index.vue` одновременно рендерились старые плавающие карточки `chatStore.floatingChats` и полноценный `FloatingMultichat`, перекрывая друг друга.
8. **Зависание эндпоинта `get_dialogs` на 31 секунду**: В `multichat.py` сотни `asyncio.create_task(redis_client.setex(...))` исчерпывали порты ОС (`OSError: [Errno 99] Cannot assign requested address`).

## 3. Выполненные действия:
1. **База данных PostgreSQL**:
   - Снято ограничение `UNIQUE` с индекса: `DROP INDEX IF EXISTS ix_vk_users_phone; CREATE INDEX IF NOT EXISTS ix_vk_users_phone ON vk_users (phone);`.
   - Удалено 355 579 мусорных строк `"Диалог MAX"`. Выполнен `VACUUM ANALYZE multichat_messages;`. Объем таблицы сократился с 450k до 94k строк.
   - В модели `backend/app/models/vk_user.py` удалено `unique=True` с поля `phone`.
2. **Бэкенд - Сообщения и имена (`vk_service.py`, `max_bridge_service.py`)**:
   - В `vk_service.py` добавлена автогенерация подписи для медиавложений без текста (`[Фотография]`, `[Стикер]`, `[Голосовое сообщение]`), обогащение именами из CRM `Customer` и безопасный откат `db.rollback()` при ошибках.
   - В `max_bridge_service.py` удалена генерация мусорных сообщений, настроено извлечение реальных имен из профилей PyMax и CRM, сохранение типов вложений.
3. **Бэкенд - Real-Time VK User LongPoll (`multichat_user_service.py`, `main.py`)**:
   - Реализован класс `VkUserLongPollManager` (`messages.getLongPollServer`, `v=5.131`).
   - Сообщения принимаются мгновенно (< 100 мс), парсятся через `messages.getById` и отправляются в WebSocket операторам. Запуск внедрен в `main.py` при старте FastAPI.
4. **Бэкенд - Пул соединений Redis и Batch MGET (`redis.py`, `multichat.py`)**:
   - В `redis.py` настроен `ConnectionPool` с `max_connections=50`.
   - В `multichat.py` одиночные запросы заменены на `await redis_client.mget(keys)` и единый `pipeline.execute()`.
5. **Фронтенд - Централизованный реактивный кэш сообщений (`chatStore.js`)**:
   - Созданы `messagesCache = ref(new Map())`, `getCachedMessages`, `setCachedMessages`, `appendMessageToCache`.
   - При WebSocket событии `multichat_message` сообщение мгновенно попадает в кэш.
6. **Фронтенд - Окно чата в заказах и основной Мультичат (`FloatingMultichat.vue`, `orders/index.vue`, `multichat/index.vue`)**:
   - При клике на диалог сообщения берутся из реактивного кэша за 0 мс (без мигания и спиннеров), а фоновый запрос тихо обновляет новые сообщения.
   - Добавлен `referrerpolicy="no-referrer"` на аватарки и медиавложения.
   - Исправлена кнопка перехода в полный мультичат на `/admin/multichat`.
   - Из `orders/index.vue` полностью удален устаревший дублирующий блок `floatingChats`.

## 4. Результаты тестирования на VPS:
- Выборка диалогов `get_dialogs`: **10.4 мс** (было 31 000+ мс — ускорение в 2000+ раз);
- История переписки `/history`: **92 мс**;
- Переключение между диалогами в интерфейсе: **0 мс** (мгновенно из памяти без спиннеров);
- Доставка сообщений личного ВК: **< 100 мс** через фоновый LongPoll;
- Аватарки и медиафайлы MAX и ВК загружаются без ошибок 403 Forbidden;
- Фронтенд успешно пересобран (`✓ built in 59.19s`), контейнеры бэкенда и воркера перезапущены.
