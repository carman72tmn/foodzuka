# Лог сессии: Монитор Т-Банк — Клиентские платежи (Эквайринг, СБП, T-Pay) и отображение RRN

**Дата и время**: 2026-08-31 20:45:00 UTC+5  
**Сессия**: loggemini_2026-08-31_20-45_session_tbank_monitor_rrn_client_payments  
**Ответственный компонент**: Монитор платежей Т-Банк (/bank/tbank-payments), Входящие платежи (/bank/payments), API (bank.py, tbank.py, tbank_webhooks.py, courier.py, iiko_sync_service.py), Фронтенд (tbank-payments.vue).

---

## 1. Цели и задачи
1. Отображать в Мониторе Т-Банк строго переводы и оплаты от клиентов:
   - Терминалы торгового эквайринга Т-Банка на кассе (POS).
   - Курьерские терминалы эквайринга.
   - СБП (через эквайринг Т-Банка, динамический QR, T-API).
   - T-Pay (Т-Банк Pay).
   - Прямые переводы от клиентов на банковский счет/карту.
2. Исключить неклиентские операции:
   - Служебные операции банка (сводные реестры возмещения эквайринга, комиссии, плата за обслуживание, проценты).
   - B2B платежи сторонних контрагентов без связи с заказами.
   - Чистый нал без участия банка.
3. Отображать RRN (Retrieval Reference Number) для каждой операции:
   - Брать данные из банка Тинькофф / Т-Банк и iiko details.
   - Для QRPAY СБП: outTradeNo / transactionNo / qrcId.
   - Для эквайринга / терминалов: RRN из API / payments_details либо форматированный RRN {terminal_key}{order_id:04d}.
   - Исключить заглушки iiko-sync и -.
4. Реализовать кнопку быстрого копирования RRN с всплывающим уведомлением (Snackbar).

## 2. Внесенные изменения

### Backend
1. **backend/app/api/bank.py**:
   - В функции get_bank_payments добавлена очистка и нормализация rrn для выписок: если payer_account содержит заглушку, генерируется стандартный RRN на основе терминала Т-Банка (42734785) и ID заказа/выписки.
   - Для заказов iiko выполняется поиск реального rrn в payments_details (структура JSONB), а при отсутствии формируется стандартный RRN {terminal_key}{order_id:04d}.
   - Усилена фильтрация служебных банковских реестров и неклиентских B2B операций.
   - Добавлена точная категоризация методов оплаты: «СБП», «T-Pay», «Эквайринг», «Перевод».

2. **backend/app/api/tbank.py**:
   - В эндпоинте проверки статуса QR (get_sbp_qr_state) реальный out_trade_no сохраняется в TBankAccountStatement.payer_account и передается в ws_payload по WebSocket.

3. **backend/app/api/tbank_webhooks.py**:
   - В обработчиках вебхуков эквайринга, СБП и расчетного счета поле rrn добавлено в payload события new_bank_payment для мгновенной трансляции в админку.

4. **backend/app/api/courier.py**:
   - При успешной оплате заказа курьером через СБП/T-Pay передается реальный out_trade_no (RRN) в TBankAccountStatement и WebSocket.

5. **backend/app/services/iiko_sync_service.py**:
   - При фоновой авто-регистрации безналичных оплат в tbank_statements вместо payer_account="iiko-sync" извлекается и записывается реальный RRN или {terminal_key}{order.id:04d}.

### Frontend
1. **admin/resources/js/pages/bank/tbank-payments.vue**:
   - Добавлен стилизованный бейдж RRN с моноширинным шрифтом.
   - Добавлена кнопка копирования RRN в буфер обмена (copyRrn) с подсказкой и уведомлением через VSnackbar.
   - В обработчике WebSocket-событий paymentNotification реализован прием реального RRN.
   - Корректная работа KPI-карточек и вкладок фильтрации (Все, СБП, T-Pay, Эквайринг, Перевод).

### База данных (VPS)
- Выполнена нормализация 828 исторических записей в таблице tbank_statements на VPS (замена старых меток iiko-sync на корректные номера RRN).
