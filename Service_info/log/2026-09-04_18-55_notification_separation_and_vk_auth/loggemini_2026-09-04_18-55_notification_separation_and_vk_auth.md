# Лог сессии: Разграничение курьерских и системных уведомлений + Авторизация сообщений ВК

**Дата и время**: 2026-09-04 18:55
**Название задачи**: notification_separation_and_vk_auth
**Статус**: Успешно выполнено и внедрено на VPS

## 1. Проблема и цели
- Было выявлено полное наложение и дублирование уведомлений в системе системных рассылок:
  - Курьерские пошаговые события (поступление заказа, смена статусов, адрес, время, состав, кухня, отмена) ошибочно отправлялись администраторам и руководителям.
  - В модальном окне «Настроить каналы рассылок» отсутствовала живая проверка авторизации сообщений от групп ВКонтакте (`messages.isMessagesFromGroupAllowed`), из-за чего бот ВК не мог доставить сообщение пользователю без предварительно открытого диалога, а администратор не понимал статус доставки.
  - Вкладка «Шаблоны» содержала дубли курьерских цепочек вместо строго системных и информационных уведомлений сотрудников (`order_new_all`, смены, закуп, системные алерты).
  - При переназначении курьера в `iiko_sync_service.py` выполнялся избыточный двойной триггер (`courier_assigned` и сразу `order_new`).

## 2. Реализованные изменения

### База данных (PostgreSQL на VPS):
- В таблицу `vk_bot_accounts` добавлены поля:
  - `allow_courier_chains BOOLEAN DEFAULT TRUE` — флаг разрешения отправки пошаговых цепочек курьера.
  - `courier_chains_vk BOOLEAN DEFAULT TRUE` — канал VK для цепочек курьера.
  - `courier_chains_tg BOOLEAN DEFAULT FALSE` — канал TG для цепочек курьера.
  - `courier_chains_max BOOLEAN DEFAULT FALSE` — канал MAX Messenger для цепочек курьера.
  - `courier_chains_sms BOOLEAN DEFAULT FALSE` — канал SMS для цепочек курьера.

### Backend (`foodtech-backend` & `foodtech-worker`):
1. `backend/app/models/vk_bot.py`:
   - Модель `VkBotAccount` дополнена новыми полями.
2. `backend/app/services/vk_bot_service.py`:
   - Реализован метод `is_messages_allowed(group_id, user_id, bot_token_override)` через VK API метод `messages.isMessagesFromGroupAllowed`.
   - Реализован метод `check_group_connection(group_id, bot_token_override)` через `groups.getById`.
3. `backend/app/services/vk_notification_router.py`:
   - Строгая изоляция курьерских цепочек: синтетическое добавление курьера к получателям выполняется строго при `event_type in courier_events` и `allow_courier_chains == True`.
   - В цикле рассылки курьерских событий отфильтрованы любые не-курьеры. Если на заказ уже назначен курьер в iiko, курьерские цепочки отправляются СТРОГО этому назначенному курьеру.
   - Поддержаны индивидуальные каналы отправки курьерских цепочек `eff_send_vk`, `eff_send_tg`, `eff_send_max`, `eff_send_sms`.
4. `backend/app/services/iiko_sync_service.py`:
   - Устранен дублирующий вызов `order_new` при переназначении курьера (сохранен только целевой `courier_assigned`). Файл сохранен в кодировке UTF-8.
5. `backend/app/api/vk_bot_admin.py`:
   - `GET /accounts/{account_id}/channel-settings`: полный снимок статуса аккаунта, групп VK с проверкой `is_messages_allowed`, прямыми ссылками на открытие диалога `https://vk.com/im?sel=-<group_id>`, настроек курьерских цепочек и динамического списка системных шаблонов из базы.
   - `POST /accounts/{account_id}/check-vk-group/{bot_id}`: живая проверка разрешения сообщений от конкретной группы через VK API.
   - `POST /accounts/{account_id}/send-test-vk-group/{bot_id}`: отправка тестового сообщения от конкретной группы ВК.
   - `POST /accounts/{account_id}/toggle-courier-chains`: включение/выключение цепочек курьера и переключение каналов доставки.
   - `POST /accounts/{account_id}/toggle-template-subscription`: включение/выключение подписки на конкретный шаблон сотрудника (по `template_id` или `event_type`) и настройка каналов.
   - `POST /accounts/{account_id}/bulk-toggle-templates`: массовые действия («Включить все», «Отключить все», включение/выключение конкретных каналов доставки для всех шаблонов сотрудника).

### Frontend (`admin/resources/js/pages/settings/vk-notifications_utf8.vue`):
1. **Вкладка «Цепочки курьера»**:
   - Добавлен акцентный бейдж «СТРОГО ДЛЯ КУРЬЕРОВ» и информационный баннер: все настройки и цепочки на этой вкладке действуют строго для курьеров iiko (`is_courier = True` и включены цепочки курьера).
2. **Вкладка «Шаблоны»**:
   - Курьерские цепочки исключены из `systemTemplates` (`!courierEventTypes.includes(t.event_type)`). На этой вкладке отображаются только системные/информационные уведомления сотрудников.
3. **Вкладка «Получатели»**:
   - В карточки сотрудников добавлен индикатор статуса курьерских цепочек («Цепочки: Вкл» / «Цепочки: Выкл»).
4. **Модальное окно «Настроить каналы рассылок»**:
   - Карточки подключенных групп VK со статусом проверки `is_messages_allowed`. Если сообщения не разрешены — прямая кнопка-ссылка «Разрешить в ВК» (`https://vk.com/im?sel=-<group_id>`) и кнопка «Проверить». При успехе — кнопка «Тест».
   - Обособленный блок «Цепочки курьера» с тумблером включения и чипсами каналов (VK, TG, MAX, SMS).
   - Динамический блок шаблонов сотрудников из базы данных `vk_templates` с тумблерами подписки, отдельными каналами и индикаторами доступности.
