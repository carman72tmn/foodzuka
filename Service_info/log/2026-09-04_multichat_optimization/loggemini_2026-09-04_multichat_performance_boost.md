# Отчет о выполнении задачи: Оптимизация и ускорение Мультичата

**Дата**: 04.09.2026  
**Сессия**: loggemini_2026-09-04_multichat_performance_boost  
**Статус**: Выполнено успешно  

## 1. Исходная проблема
Пользователь обратился с проблемой:
- Медленно загружаются и читаются чаты в Мультичате (vezuroll.ru/admin/multichat).
- Сообщения доходят с задержкой.
- Открытие и подгрузка переписок в старых и новых чатах перегружает систему.

## 2. Проведенная диагностика и найденные корневые причины
1. **Катастрофический Table Bloat в PostgreSQL из-за multichat_user_service.py**:
   - Каждую минуту при синхронизации личного ВК запускался:
     UPDATE multichat_messages SET peer_name = ..., peer_avatar = ... WHERE channel = 'vk_user' AND peer_id = peer_id;
   - В БД есть диалоги с 23 919 и 22 467 сообщениями. Каждую минуту перезаписывались десятки тысяч строк. Это создавало миллионы мертвых строк, раздувало БД до 10 ГБ и приводило к зависаниям дискового ввода-вывода.
2. **Тяжелый запрос диалогов GET /dialogs (1.031 секунды)**:
   - CTE sql_fast_dialogs запрашивал SELECT *, вычитывая мегабайты JSONB TOAST-данных payload для 346 чатов.
   - Поиск профилей собеседников без кэша повторно сканировал таблицу сообщений через ~ilike('%пользователь%').
3. **Чрезмерный рендер сайдбара во фронтенде**:
   - Все 346 диалогов со всеми кнопками, аватарками, значками и меню рендерились одновременно.
   - Каждые 10 секунд фоновый silentSync перезапрашивал полный список и вызывал диффинг сотен компонентов.
4. **Задержка доставки входящих из личных аккаунтов**:
   - В scheduled_tasks интервал стоял на 60 секунд.
   - В vk_service.py для сообщений сообщества ВК не вызывалась инвалидация кэша диалогов.

## 3. Выполненные работы
1. **backend/app/services/multichat_user_service.py**:
   - Полностью удален массовый UPDATE исторических строк.
   - Реализована функция safe_async_run для безопасного вызова асинхронных операций из синхронных воркеров.
   - Данные профиля собеседника кэшируются в Redis (multichat:profile:vk_user:{peer_id}) на 24 часа.
2. **backend/app/api/multichat.py**:
   - SQL-запрос sql_fast_dialogs облегчен: поле payload исключено из выборки списка диалогов (NULL::jsonb as payload), что избавило от сканирования TOAST.
   - Внедрен Redis-кэш профилей собеседников multichat:profile:fast:{peer_id} (TTL 24 часа).
   - В get_history поиск профиля собеседника для больших чатов переведен на чтение из Redis за <1 мс.
3. **backend/app/services/vk_service.py**:
   - Доставка сообщений сообщества ВК переведена на централизованную await broadcast_ws_message(multichat_msg) с моментальной инвалидацией кэша.
4. **admin/resources/js/pages/multichat/index.vue**:
   - Внедрен лимит отображения displayedDialogs (первые 60 диалогов с кнопкой подгрузки), снизивший DOM-нагрузку в 6 раз.
   - Интервал фонового silentSync увеличен с 10 до 25 секунд для разгрузки сети при живом WebSocket.
5. **База данных (scheduled_tasks)**:
   - Интервал синхронизации личного ВК и личного MAX снижен с 60 секунд до 15 секунд (выполняется за 0.03 с без нагрузки на БД).
