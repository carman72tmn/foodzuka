# Лог исследования: Диагностика генерации СБП QR-кодов Т-Банка
**Дата**: 18.06.2026 20:35 (UTC+5)

## Описание задачи
Выяснить, почему при нажатии кнопки "Оплата по СБП" в панели курьера генерируется демо-код вместо реального QR-кода оплаты через Т-Банк.

## Выполненные шаги диагностики
1. Изучен бэкенд роут `POST /orders/{order_id}/sbp-qr` в `backend/app/api/courier.py`. Обнаружено, что при любых исключениях или ошибках API Т-Банка роут молча переключается в fallback-режим и отдает демо QR-код.
2. Проверен статус настроек Т-Банка в БД на VPS:
   - `is_active` = True
   - `terminal_delivery` = `2332089853` (задан)
   - `token` = задан (длина 88 символов)
   - `certificate_content` = задан (длина 2309 символов)
3. Создан и запущен на VPS диагностический скрипт `diag_tbank_sbp.py` для тестирования прямого mTLS-подключения к Т-Банку.
4. Выявлена ошибка при загрузке SSL-контекста:
   `ssl.SSLError: [SSL] PEM lib (_ssl.c:3948)`
5. Проведен анализ структуры PEM-сертификата в БД:
   - Обнаружен только блок `-----BEGIN CERTIFICATE----- ... -----END CERTIFICATE-----` (публичный сертификат).
   - Приватный закрытый ключ (`-----BEGIN PRIVATE KEY-----`) полностью отсутствует.

## Вывод и решение
Для работы API Т-Банка (OpenAPI / T-API Бизнес) по протоколу Mutual TLS (mTLS) в поле `certificate_content` (настройки Т-Банка в панели администратора) должен быть загружен PEM-файл, содержащий **одновременно** публичный сертификат и закрытый приватный ключ.
В данный момент приватного ключа нет, поэтому SSL-подключение падает, и бэкенд выдает демо QR-код.
Необходимо объединить приватный ключ и сертификат в один PEM-текст и обновить настройки Т-Банка в админ-панели.
