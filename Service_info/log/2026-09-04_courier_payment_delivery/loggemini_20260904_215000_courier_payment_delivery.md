## 1. Постановка задачи
1. В разделе панели курьеров (`/pers/courier`):
   - При нажатии кнопки **«Доставлен»** проверять, указан ли у заказа способ оплаты (`payment_method`, `payments_details`).
   - Если способ оплаты **не указан**: запрашивать у курьера подтверждение и выбор фактического способа оплаты («Наличные», «Картой курьеру», «Сплит», «СБП»), и только после выбора и сохранения способа переводить доставку в статус `Delivered`.
   - Если способ оплаты уже указан: переводить в статус `Delivered` без лишних диалогов.
2. По кнопке **«Оплата»**:
   - Автоматически отображать **активным** тот способ оплаты, который уже выбран на кассе в iiko (устранить инверсию, снять блокировку `:disabled` с текущего способа оплаты, добавить бейдж `Текущий в iiko`).
   - При смене способа оплаты курьером отправлять изменения в iiko Cloud API (`/api/1/deliveries/change_payments`).
3. **Критически важное требование по бонусам**:
   - Если в заказе iiko есть оплата бонусами (бонусная система, `iikoCard`, `LoyaltyCard`), **их ни в коем случае не удалять и не перезаписывать**, а сохранять в массиве `payments`.
   - Курьерскую оплату начислять **строго на остаточную стоимость** чека (за вычетом бонусов), чтобы сумма всех оплат в точности равнялась сумме чека iiko.

## 2. Исследования на VPS и выявленные особенности iiko Cloud API
1. В эндпоинте iiko Cloud `/api/1/deliveries/by_id` объект заказа вложен в поле `res["order"]`.
2. В заказах с бонусами (например, заказ №2804 с чеком 1695 ₽ и списанием 71 бонуса):
   - Платеж бонусами имеет имя `"Бонусная система"`, а `kind` возвращается как `"Unknown"`.
   - В справочнике `payment_types` зарегистрирован ID 9 (`6524f99d-d2fe-43c2-bec1-46e07134b338`, name: `'Бонусная система'`, kind: `'IikoCard'`).
   - Остаточная сумма к оплате курьеру: `1695 - 71 = 1624 ₽`.

## 3. Выполненные доработки

### 3.1. Бэкенд (`backend/app/api/courier.py`)
1. **`_extract_bonus_payments(iiko_order, order, db)`**:
   - Надежно извлекает существующие бонусные платежи из `(iiko_order.get("order") or iiko_order).get("payments")`.
   - Фильтрует по `kind` (`iikocard`, `loyaltycard`) и по названию (`"бонус"`, `"bonus"`).
   - Сверяет ID со справочником `PaymentType` в локальной БД для точного указания `kind="IikoCard"`.
   - Включает безопасный фоллбэк: если iiko не вернул массив оплат, но в локальной БД `order.bonus_spent > 0`, восстанавливает платеж бонусами.
2. **`_calculate_residual_sum(order, bonus_payments, target_amount)`**:
   - Рассчитывает остаток к оплате строго как: `total_amount - bonus_sum`.
3. **`_apply_order_payment_to_iiko(db, order, settings, payment_type_id, current_user, amount)`**:
   - Формирует итоговый массив: `final_payments = bonus_payments + [new_payment]`, где курьерский платеж идет ровно на сумму остатка.
   - Отправляет в `iiko_service.change_order_payments`.
4. **Эндпоинты API**:
   - `POST /api/v1/courier/orders/{order_id}/change-payment-type`: обновлен для сохранения бонусов.
   - `POST /api/v1/courier/orders/{order_id}/close`: обновлен для сохранения бонусов.
   - `POST /api/v1/courier/orders/{order_id}/status`: добавлен параметр `payment_type_id: Optional[str] = None` с фиксацией оплаты при переводе в `Delivered`.

### 3.2. Фронтенд (`admin/resources/js/pages/employee/courier.vue`)
1. **Функция `hasOrderPaymentMethod(order)`**:
   - Проверяет онлайн-оплату (`is_paid && left_to_pay <= 0`).
   - Проверяет элементы `payments_details.items`, отфильтровывая бонусные платежи.
   - Проверяет текстовое поле `payment_method` на `"Не указан"`, `"—"`, пустую строку или чисто бонусное списание.
2. **Обработчик `handleDeliveredClick(order)`**:
   - Привязан к кнопке «Доставлен» в карточке заказа.
   - Если способ оплаты не указан: выводит подсказку и открывает диалог выбора способа оплаты в режиме подтверждения доставки (`isDeliveryConfirmation = true`).
   - Если способ оплаты указан: немедленно переводит заказ в статус `Delivered`.
3. **Диалог выбора и смены оплаты (`showChangePaymentDialog`)**:
   - Устранена инверсия в `openChangePaymentDialog`: если на кассе iiko выбран `Cash` — активным сразу устанавливается `Cash`; если `Card` — `Card`; если `Split` — раскрывается режим сплита с предзаполненными суммами.
   - Снято ограничение `:disabled` с текущего способа оплаты, добавлен понятный бейдж `Текущий в iiko`.
   - Добавлена кнопка быстрого перехода к генерации динамического СБП QR («Оплата по СБП (QR-код)»).
   - В режиме подтверждения доставки заголовок переключается на «Подтверждение доставки», плашка предупреждает о необходимости выбрать способ расчета, а кнопка действия меняется на «Подтвердить и доставить».
   - В `submitPaymentChange`: при сохранении в режиме подтверждения доставки после вызова `/change-payment-type` заказ автоматически переводится в `Delivered`.
