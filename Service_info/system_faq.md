## Инфраструктура фоновых задач (Celery)

Для выполнения длительных операций (массовая синхронизация, импорт из файлов, рассылки) используется **Celery** с **Redis** в качестве брокера сообщений.

### Компоненты:

- **Broker**: `redis://redis:6379/0` (контейнер `foodtech-redis`)
- **Worker**: Отдельный Docker-контейнер `foodtech-worker`, запускающий `celery -A app.core.celery_app worker`.
- **App**: Конфигурация находится в `backend/app/core/celery_app.py`.
- **Задачи**: Определены в `backend/app/tasks/customer_tasks.py`.

## Интеграция с iiko (OLAP)

Для синхронизации доставок и выручки курьеров используются OLAP-отчеты iiko Server (Resto API).

### Основные поля для отчета DELIVERIES:

- **Тип отчета**: `DELIVERIES`
- **Обязательный фильтр**: `OpenDate.Typed` (Учетный день)
- **Группировка (groupByRowFields)**:
  - `Delivery.Number` — Номер доставки
  - `Delivery.Courier` — ФИО курьера
  - `Delivery.Street` — Улица
  - `Delivery.Region` / `Delivery.Zone` — Зона доставки
- **Агрегация (aggregateFields)**:
  - `fullSum` — Полная сумма заказа
  - `UniqOrderId` — Уникальный ID заказа (обязательно для предотвращения 422 ошибки)

## Синхронизация клиентов (Customers)

### 1. Массовая синхронизация (Рекурсивная схема)

- **Размер пачки**: 50 клиентов.
- **Пауза**: 50 секунд между пачками.
- **Логика**: Рекурсивный вызов Celery задач с инкрементом `skip`.
- **Управление**: Можно поставить на паузу или отменить через страницу "Фоновые процессы".

### 2. Импорт клиентов из файлов (XLSX, XML)

- **Эндпоинт**: `POST /api/v1/customers/import`
- **Логика**: Файл загружается в `backend/temp_imports/`, затем запускается фоновая задача.

### 3. Авто-создание при заказе (Обновлено 26.04.2026)

В `iiko_sync_service.py` реализован метод `ensure_customer_from_order`:

- **Триггер**: Поступление заказа с сайта, из бота или через вебхук iiko.
- **Проверка**: Поиск по номеру телефона в таблице `customers`.
- **Действие**: Если гостя нет, создается новая карточка. Если есть — обновляются данные.
- **Синхронизация**: Сразу запускается фоновая задача `sync_single_customer_task`.

### 4. Расширенная карточка клиента (Laravel + Vue.js) (Обновлено: 28.04.2026)

- **Вкладка "Бонусы"**: Отображает текущий баланс кошельков и полную историю транзакций.
- **Вкладка "Адреса"**: Список всех адресов доставки клиента.
- **История Заказов (12 мес)**: Загрузка истории доставок из iiko Cloud с возможностью просмотра деталей.
- **Аналитика**: Глубокая статистика LTV, средний чек и частота заказов через OLAP.

### 16. Исправление ошибок API Клиентов (PUT & OLAP) [NEW 28.04.2026]

- **Метод PUT**: В роутер `/api/v1/customers/{customer_id}` добавлена поддержка метода `PUT`. Это устраняет ошибку `405 Method Not Allowed`.
- **Корректировка бонусов**: Исправлена ошибка `Could not find bonus wallet for this customer`. Бэкенд теперь проверяет и `id`, и `walletId`. 
  - **Устранение 500 ошибки**: Метод `add_customer_balance` теперь выбрасывает `ValueError` с текстом ошибки от iiko. API перехватывает это и отдает 400 с понятным описанием (например, "Недостаточно прав" или "Кошелек заблокирован"). Это заменяет общую 500 ошибку на информативное уведомление.
### Синхронизация иконок (Icons)
- **Технология**: Используется Iconify с интеграцией в Vuetify.
- **Динамическая загрузка**: Любая иконка с префиксами `mdi-`, `ri-`, `bx-`, `fa-` подгружается автоматически через Iconify API.
- **Локальный бандл**: Основные наборы (Boxicons, MDI, Remix Icons) собираются в `admin/resources/js/plugins/iconify/icons.css` для мгновенного отображения.
- **Добавление новых наборов**:
  1. Установить пакет: `npm install --save-dev @iconify-json/{prefix}`
  2. Добавить в `build-icons.js` в секцию `json`.
  3. Запустить `npm run build:icons`.
  4. Добавить префикс в `knownPrefixes` в `admin/resources/js/plugins/vuetify/icons.js`.
- **Синхронизация профиля клиента (Экспорт)**:

* При сохранении изменений в админке запускается `export_customer_to_iiko_task`.
* **Маппинг пола (sex)**: 0 (Not specified), 1 (Male), 2 (Female).
* **Структура Payload**: Плоская (Flat structure), `organizationId` и данные клиента на одном уровне.
* **Поле фамилии**: `surName` (camelCase).
* **Формат даты**: `yyyy-MM-dd HH:mm:ss.fff`.

### 20. Стабилизация выручки, рисков и кодировки [NEW 29.04.2026]

- **Синхронизация выручки**: 
  - Изменена логика обновления `revenue_at_close` в `iiko_sync_service.py`. Теперь выручка в закрытых сменах обновляется всегда, если она отличается от данных OLAP (ранее обновлялась только при нулевом значении). Это решает проблему расхождений в отчетах (например, за 20.04.2026).
- **Синхронизация Рисков (Hardened)**:
  - Для обеспечения совместимости с различными версиями iiko Cloud API, статус высокого риска теперь отправляется в двух полях одновременно: `shouldBeCheckedForRisk` и `isHighRisk`.
- **Гарантия UTF-8**:
  - Во всех ключевых методах `iiko_service.py` (включая получение токена) добавлена принудительная установка `response.encoding = 'utf-8'`. Это устраняет проблему появления знаков вопроса (`???`) в данных заказов и именах клиентов.
- **Иконки (VPS)**:
  - На сервере выполнен полный цикл сборки иконок: `npm install @iconify-json/ri`, `npm run build:icons` и `npm run build`. Это гарантирует корректное отображение Remix Icons во всей админ-панели.
