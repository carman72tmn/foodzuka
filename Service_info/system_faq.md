## Инфраструктура фоновых задач (Celery)

Для выполнения длительных операций (массовая синхронизация, импорт из файлов, рассылки) используется **Celery** с **Redis** в качестве брокера сообщений.

### Компоненты:

- **Broker**: `redis://redis:6379/0` (контейнер `foodtech-redis`)
- **Worker**: Отдельный Docker-контейнер `foodtech-worker`, запускающий `celery -A app.core.celery_app worker`.
- **App**: Конфигурация находится в `backend/app/core/celery_app.py`.
- **Задачи**: Определены в `backend/app/tasks/customer_tasks.py`.

## Интеграция с iiko (OLAP)

Для синхронизации доставок и выручки курьеров используются OLAP-отчеты iiko Server (Resto API).

### Основные поля для отчета DELIVERIES:

- **Тип отчета**: `DELIVERIES`
- **Обязательный фильтр**: `OpenDate.Typed` (Учетный день)
- **Группировка (groupByRowFields)**:
  - `Delivery.Number` — Номер доставки
  - `Delivery.Courier` — ФИО курьера
  - `Delivery.Street` — Улица
  - `Delivery.Region` / `Delivery.Zone` — Зона доставки
- **Агрегация (aggregateFields)**:
  - `fullSum` — Полная сумма заказа
  - `UniqOrderId` — Уникальный ID заказа (обязательно для предотвращения 422 ошибки)

### 29. Фоновое обогащение данных клиента [NEW 01.05.2026]

Для отображения расширенной статистики в карточке гостя реализован механизм асинхронного обновления данных из iiko.

**Логика работы:**

1. **При открытии карточки гостя:** Фронтенд сразу получает "быстрые" данные из БД.
2. **Фоновое обновление:** Одновременно запускается запрос к эндпоинту `/olap-stats`, который тянет свежие данные из iiko.
3. **Кэширование:** Полученные из iiko данные автоматически обновляют запись в БД `customers`.
4. **Индикация:** Во время фонового обновления в UI отображаются спиннеры (`VProgressCircular`) рядом с полями.

**Обновляемые поля:**

- `first_order_date` (Дата первого заказа)
- `total_discount` (Сумма всех скидок)
- `total_items` (Общее количество купленных товаров)
- `average_check` (Средний чек)
- `frequency_days` (Средняя частота заказов в днях)
- `days_since_last_order` (Дней с последнего заказа)

### 45. Исправление ошибки синхронизации заказов (fast_only) (05.05.2026) [NEW]
**Проблема**: Ошибка `IikoSyncService.sync_orders() got an unexpected keyword argument 'fast_only'` в разделе Курьеры.
**Причина**: Метод `sync_orders` не принимал параметр `fast_only`, который вызывался из API курьеров.
**Решение**:
1. Обновлена сигнатура метода `sync_orders` в `iiko_sync_service.py`, добавлены параметры `fast_only` и `skip_revision`.
2. Реализован "быстрый" режим: при `fast_only=True` выполняется синхронизация только по ревизиям (если не указано `skip_revision`) или опрос за последние 4 часа (вместо 24).
3. Проведена очистка метода от дублирующегося кода получения настроек.

### 51. Исправление ошибки смены оплаты курьером в iiko (29.10.2026) [NEW]
**Проблема**: В админке и панели курьера при закрытии заказа с выбором способа оплаты («Подтвердить и доставить») возникала ошибка 400 Bad Request от iiko Cloud API (`/api/1/deliveries/change_payments`: `Value cannot be null. (Parameter 'paymentAdditionalData')`).
**Причина**:
1. В заказах со списанием бонусов iikoCard сумма бонусов учитывается в iiko как скидка (`discounts`). Фолбэк `_extract_bonus_payments` генерировал фиктивный платеж с невалидным `paymentTypeKind="IikoCard"` без обязательного `paymentAdditionalData`, превышая сумму чека iiko.
2. Отсутствовала проверка `payments_already_match`: при подтверждении курьером уже установленного в iiko типа оплаты отправлялся избыточный запрос к API, вызывавший сбой, если чек уже был напечатан.
**Решение**:
1. В `_extract_bonus_payments` добавлена проверка наличия бонусов в `discounts`: если бонусы уже в скидках, они не добавляются в `payments`, предотвращая ошибку 400.
2. В `_calculate_residual_sum` сумма остатка к оплате берется строго как `total_with_discount` чека iiko.
3. Добавлена проверка совпадения оплат `payments_already_match`: если способ оплаты совпадает с iiko, лишний вызов `change_payments` пропускается.
4. Добавлена безопасная обработка закрытых/обработанных на кассе заказов, предотвращающая зависание курьера.
